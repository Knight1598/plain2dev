Plain2Dev คือแพ็กเกจสกิลสำหรับ Coding AI มันอ่านคำสั่งภาษาไทยหรืออังกฤษ ถามเฉพาะเรื่องที่ถ้าตอบต่างกันแล้วผลลัพธ์จะเปลี่ยน สรุปให้คุณตรวจก่อนลงมือ แล้วเรียบเรียงเป็นข้อกำหนดที่ตรวจรับได้ จากนั้นจดการตัดสินใจไว้ในโปรเจกต์ เพื่อให้ session ถัดไปไม่ต้องเริ่มจากศูนย์

มันไม่ใช่ตัวเขียนโค้ด และไม่ใช่แชตบอตห่อทับ AI มันคือชั้นที่อยู่ระหว่าง "อยากให้หัวหน้าใส่เหตุผลตอนปฏิเสธการเบิก" กับข้อกำหนดที่มีเกณฑ์ตรวจรับและผ่านการรีวิวได้

## ติดตั้ง

**แบบปลั๊กอิน Claude Code** — แนะนำ:

```bash
claude plugin marketplace add Knight1598/plain2dev
```

```bash
claude plugin install plain2dev@plain2dev
```

**แบบติดตั้งในโปรเจกต์** — ใช้ได้กับ Codex, Claude Code หรือ AI อื่น ไม่ต้องสมัครบัญชี:

```bash
npx github:Knight1598/plain2dev --target . --agent codex
```

> **Windows PowerShell:** ให้พิมพ์ `npx.cmd` แทน `npx` เพราะ PowerShell ปฏิเสธการรันไฟล์ `npx.ps1` ที่มากับ Node ตามนโยบายความปลอดภัยเริ่มต้นของ Windows การใช้ `npx.cmd` เลี่ยงปัญหาได้โดยไม่ต้องลดความปลอดภัยของเครื่อง

**จากไฟล์ที่ดาวน์โหลดมา:**

```bash
node scripts/install.mjs --target /absolute/project/path --agent claude
```

```bash
node scripts/install.mjs --target /absolute/project/path --check
```

ต้องมี Node.js 18 ขึ้นไป ไม่มี dependencies ไม่มีเซิร์ฟเวอร์ ไม่ต้องใช้ API key เลือก agent ได้: `codex`, `claude`, `both`, `generic` ใส่ `--dry-run` เพื่อดูก่อน หรือ `--uninstall` เพื่อถอน

ตัวติดตั้งไม่แก้ `AGENTS.md` หรือ `CLAUDE.md` เดิมของคุณ ไม่แตะ config ระดับเครื่อง และรักษาไฟล์ความจำของโปรเจกต์ไว้ครบทุกไบต์เมื่ออัปเกรด

## วิธีใช้

ใน Claude Code:

```
/plain2dev อยากให้หัวหน้าใส่เหตุผลตอนปฏิเสธการเบิกของ
```

ใน Codex พิมพ์ `$plain2dev` แล้วตามด้วยคำสั่ง ส่วน AI อื่นให้บอกมันอ่าน `.plain2dev/engine/SKILL.md`

สิ่งที่ได้กลับมาคือสรุปว่ามันเข้าใจอะไร คำถามเท่าที่จำเป็นจริง ๆ และข้อกำหนด:

> **REQ-0003 r1** — ปฏิเสธต้องมีเหตุผล
> - เหตุผลเป็นข้อมูลบังคับ ตรวจฝั่งเซิร์ฟเวอร์ว่าไม่ว่าง บันทึกคู่กับการปฏิเสธ และแสดงให้ผู้ขอเบิกเห็น
> - คงเดิม: ขั้นตอนอนุมัติ การตัดสต๊อก การแจ้งเตือน ระบบสิทธิ์
> - ไม่รวมในงานนี้: แจ้งเตือน LINE (เป็นข้อเสนอ ยังไม่ได้ตกลง)
> - เกณฑ์ตรวจรับ: เหตุผลว่างต้องปฏิเสธไม่ได้ / ใส่เหตุผลแล้วบันทึกและเห็นหลังรีโหลด / พฤติกรรมการอนุมัติไม่เปลี่ยน

แก้ความเข้าใจได้ตลอด — "แก้ใหม่ ให้ตัดสต๊อกทันที" — มันจะทำให้ข้อกำหนดเดิมเป็น superseded อย่างชัดเจน แทนที่จะแอบเขียนประวัติใหม่

## ข้างในมีอะไร

| ส่วน | หน้าที่ |
| --- | --- |
| Intent Engine | แยกว่าอะไรคือสิ่งที่คุณสั่ง อะไรคือสิ่งที่ AI สมมติเอง อะไรแค่เสนอ และอะไรยังไม่มีใครรู้ |
| Question Engine | ถามรอบละ 1–3 ข้อ เฉพาะจุดที่คำตอบต่างกันแล้วผลลัพธ์เปลี่ยน |
| Context Router | เริ่มจากแผนที่โปรเจกต์และไฟล์ที่ระบุชื่อ ตรวจก่อนเชื่อ และแก้แผนที่ที่ล้าสมัย |
| Token Engine | เลี่ยงการอ่านและสรุปเรื่องเดิมซ้ำ โดยไม่ตัดข้อกำหนดหรือการทดสอบทิ้ง |
| Change Ledger | บันทึกว่าทำไมข้อกำหนดถึงเปลี่ยน กระทบอะไร และตรวจอะไรไปแล้วจริง |

ความจำเก็บในโปรเจกต์ปลายทางใต้ `.plain2dev/` — แผนที่ฟีเจอร์ ดัชนีข้อกำหนดที่เลขรูปแบบ `REQ-0001 r1` และประวัติการเปลี่ยนแปลงที่ลงวันที่ ทั้งหมดเป็น Markdown ธรรมดาที่อ่าน diff และแก้เองได้ Git เป็นเจ้าของ diff ส่วน ledger เป็นเจ้าของเจตนา

## อะไรวัดแล้ว อะไรยังไม่ได้วัด

ส่วนนี้สำคัญกว่ารายการฟีเจอร์

**ผ่านการทดสอบแล้ว** (`node --test` 25 เคส): การติดตั้ง การอัปเกรดข้ามชุดไฟล์ที่เปลี่ยน การลบไฟล์ตกค้าง การเพิ่ม/ถอน adapter การตรวจจับไฟล์ที่ถูกแก้ การปฏิเสธ symlink และ path traversal การตรวจ manifest ที่ถูกแก้ การรักษาความจำ และการถอนติดตั้ง

**ยังไม่ได้วัด:** ลดค่าโทเคนได้เท่าไร ในแพ็กเกจนี้ไม่มีการอ้างตัวเลขเปอร์เซ็นต์ที่ไหนเลย เพราะยังไม่ได้รัน benchmark เปรียบเทียบ ไฟล์ [`tests/BENCHMARK.md`](tests/BENCHMARK.md) คือโปรโตคอลที่จะให้ตัวเลขนั้น — 8 เคส 2 arm รันเคสละ 3 ครั้ง ใช้เฉพาะตัวเลข usage ที่ผู้ให้บริการรายงาน จนกว่าตัวเลขจะมีจริง สิ่งที่แพ็กเกจนี้เสนอคือข้อกำหนดที่มีขอบเขตชัดและโปรเจกต์ที่จำการตัดสินใจของตัวเองได้ ไม่ใช่ตัวเลขประหยัด

การทดสอบพฤติกรรมอยู่ใน [`evals/`](evals/) รันด้วย `claude plugin eval .` ซึ่งจะให้คะแนนเทียบกับกรณีไม่โหลดปลั๊กอิน
